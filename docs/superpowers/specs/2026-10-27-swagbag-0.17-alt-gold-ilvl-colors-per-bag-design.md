## 2. Alt gold and currencies

**Saved.** For each character, SwagBag's own store (SwagBagDB.chars[key], beside class, level and the
snapshots) gains `money` (copper) and `currencies` ({ [currencyID] = quantity }). Written at login once the
money is known, on PLAYER_MONEY and CURRENCY_DISPLAY_UPDATE (debounced, like the footer), and on logout.
Which currencies: every one the footer can show (the backpack-ticked ones and every crest the character
owns), so a tooltip never asks about a currency nobody saved. A secret or missing value is not written: the
last good one stays. No new chat lines; /swagbag report gains one line (characters with gold saved).

**Read.** Through Engine/AltData.lua, one new provider call, `money(key)` / `currencies(key)` ->
value | nil, like `counts`: the Syndicator provider answers from Syndicator's saved characters when it has
them (money and currencies), else the Own provider answers. So with Syndicator installed every alt shows at
once; without it, an alt shows after its first login with 0.17.

**Shown.**
- Hovering **gold** in the footer: the current character's gold as now (gold, silver and copper), then
  every character with gold saved, richest first, name in class color and the whole gold pieces; then the
  warband bank's gold (Adapter.WarbandMoney; last known when the bank is not open) and a **Total** line.
  Characters with 0 gold are left out. More than 20 characters: the 20 richest, then "N more".
- Hovering a **currency or crest**: Blizzard's own currency tooltip as now, then one line per character
  that has some of it, most first, same color rule, same 20 cap.
- No alt saved yet: one gray line, "Log in on your other characters once to add them here."
- Every character of the account the provider knows, from every realm; the realm is shown only when two
  characters share a name.

## 3. Item-level colors

**Settings** (plain values, like every other setting, so per-character overrides, profiles and share strings
carry them unchanged): `overlays.ilvlColors` (boolean, default false) and `overlays.ilvlSteps` (text, default
""), up to 4 steps written "680:green,690:blue,700:purple". Colors come from a fixed palette, Blizzard's own
quality colors: gray, white, green, blue, purple, orange (the Settings window has no color-picker row, and
these are the colors players read item levels in).

**Settings > Overlays** gains "Color item levels" (Off / On) under the item-level row. Turning it on the first
time (steps empty) fills them from the equipped item level (rounded down): that level green, +10 blue, +20
purple. Then 4 pairs of rows: "Level N" (a number box; empty removes that step) and "Color N" (the six colors).
Turning it off keeps the steps for next time. No equipped level known (data not loaded): the steps stay empty
and a note row says to set the levels by hand. Also `/swagbag ilvlcolors on|off`.

**Rule.** An item level gets the color of the highest step it reaches; below the lowest step it stays
white. Steps are applied sorted by level whatever order the rows are in; two steps with one level: the lower
row wins. Applies to the number on item icons (bags, banks, guild bank, alt viewer) and to the list view's
item-level column. Keystone levels ("+12") are not item levels and stay as they are.

## 4. Per-bag view

**Switching.** The bags window's view button cycles categories -> list -> grid -> **bags** -> categories; the
bank window's "..." menu, which lists the views, gains a fourth row "Bags". `bags.view` and `bank.view` accept
`"bags"`; the guild bank's cycle (GroupView.VIEW_NEXT) is unchanged. `/swagbag view bags` and the help text
that names the views gain it.

**Bags window.** One section per bag in physical order: Backpack, bags 1 to 4, then the reagent bag. Header:
the bag's name (the equipped bag's item name; "Backpack" for bag 0), its slot count and free slots
("Wildercloth Bag · 36 slots · 10 free"). Slots in physical order with empty slots in place. Click a header to
collapse it, saved per character like other sections (key by bag ID, so swapping a bag keeps the fold).

**Bank window.** For the bank shown (character or warband), one section per purchased tab, in tab order:
the tab's own name (as set in Blizzard's bank), its slot count and free slots.

**Same as the grid view:** no New or Free sections, no stack grouping, focus modes do not reorder or fold
it, the free tile is not used. **As every view:** search dims non-matches, overlays, the new-item glow,
drag and drop, right-click to the open bank, Safe Mode.

## Error handling

- A provider that throws on money/currencies is handled as today (three strikes, then switched off).
- A step row with a non-number level is not saved; the box shows the last good value.
- A bag or tab whose name cannot be read shows "Bag N" / "Tab N".
- Read-only settings (Safe Mode): the color rows and the view button answer as today (no write, a title line).

## Testing

busted, in the style of the existing specs: AltData money/currency provider order (Syndicator first, Own
fallback, a failing provider), the store writes (secret values skipped), the tooltip line order, cap and
empty case; the color rule (sorting, ties, below lowest, keystone untouched) and the first-tick fill; the
view cycles (bags, bank, guild bank unchanged), per-bag sections and headers, collapse keys, and that
New/Free/stack grouping/focus are off in it. In-game checklist for the parts the desk cannot see (tooltip
looks, the colors on real items, real bag and tab names), as in earlier weeks.
