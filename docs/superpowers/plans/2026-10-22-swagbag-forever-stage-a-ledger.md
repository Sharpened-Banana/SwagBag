### Findings and rulings

- **F1 (High; T2 vs check.sh / Adapter rule).** The comment that T2 requires in `UI/SafeModeHooks.lua`, "the bag-bar IDs from Enum.BagIndex; ...", matches `check.sh`'s `Enum\.` rule outside the Adapter. Task 2 can never print ALL CHECKS PASSED.
  Ruling: change the mandated comment to "the bag-bar IDs from the Adapter's bag layout; never bank tabs, nil or other values" — `check.sh` greps comments too — Task 2's gate fails, and an implementer might "fix" it by weakening check.sh.
- **F2 (Med; T2 vs Global Constraints, detection rule).** `Checks.Run` (Core/Checks.lua) calls `A.Flavor()`, but the constraint names Report as the only exception.
  Ruling: add `A.CheckExpected(c)` to the Adapter (it returns `c.foreverValue` on Forever, else `c.value`) and have `Checks.Run` call it. That keeps every flavor read inside the Adapter and Report — the constraint stays true without editing it — an unreviewed second exception invites more flavor tests outside the table.
- **F3 (Med; T2 vs "every Adapter read takes the same path as today"; Retail risk).** On Retail, `BagKind` and `GetBagIDs("bags")` now read the live `Enum.BagIndex`. Retail stays byte-for-byte only if the live table derives exactly today's literals. Task 2 pins that against a copied table, not against the client.
  Ruling: keep the derivation on both clients (the report's §2/§3 step 3 asks for it), reword the constraint to "same results as today, pinned by Task 2's Retail-table test", and have the Task 2 implementer paste the live-branch source table verbatim — a whole-table fallback plus the required `AccountBankTab_1 == 12` check already catch a renumbered Retail table — if wrong, a future Retail patch silently relabels bank tabs, exactly as the literals would have.
- **F4 (Med; T4).** The guild notice is wired to `GUILDBANKFRAME_OPENED`, which the code calls the "older clients" event. Midnight (and so Forever) opens the guild bank through `PLAYER_INTERACTION_MANAGER_FRAME_SHOW` → `GW.OnOpened`.
  Ruling: call `SB.SafeMode.ForeverNotice()` at the top of `GW.OnOpened` (both paths reach it), and fire the interaction event in the forever_spec guild test — the requirement is "says so once at the first bank or guild-bank visit" — if wrong, a Forever guild-bank-first player gets no explanation, and checklist F-8 passes vacuously.
- **F5 (Med; T4 test asserts nothing).** "On Forever the warband bank is never saved" cannot fail under its mutation, because the Forever mock has `warband = {}` and `store` skips an empty capture. The PLAYER_LOGOUT `capture("warband")` path is also outside `Save`.
  Ruling: put the gate in `Snap.Capture`, or as one early return used by `Save` and the logout capture. In the test, set `m.bagIDs.warband = { 15 }` with an item, so that only the gate keeps `SwagBagDB.warband` nil — otherwise the test is a defect a reviewer would flag — if wrong, the code is redundant but unguarded, and a later edit can reintroduce warband snapshots on Forever.
- **F6 (Med; T5).** `scripts/interfaces.lua` is both a module and a CLI. If it detects the CLI through the global `arg`, it runs (prints and exits 1) when dofile'd from `spec/runner.lua`, whose `arg` holds spec paths, and from toc_check.
  Ruling: detect the CLI only with `local cli = select("#", ...) > 0` at the main chunk (dofile passes no varargs), or move the CLI to a tiny wrapper — `os.exit(1)` inside the test runner kills the whole suite — if wrong, `check.sh` step 5 dies with no test output.
- **F7 (Low-Med; T3 test contradicts code).** The overlays test expects `topLeft == ""` "while the item level still draws", but `topLeft` holds the item level (Overlays.lua:184-186).
  Ruling: assert the gear item's `bottomLeft == ""` with `topLeft == ilvl`, and the keystone's `topLeft == ""` and `bottomLeft == ""` — as written the test can never pass — the implementer would otherwise bend the code or drop the assertion.
- **F8 (Low; T3 footer text).** The test is titled "moving gold down" but its body moves currencies. `F.Position` still counts hidden entries, so `FOOTER_MOVED` would say "number 5" when only 3 entries show. `FOOTER_NOTE` still mentions Crests on Forever.
  Ruling: rename the test "moving currencies down passes the hidden crests"; make `F.Position` count in `F.Shown()` (on Retail it is identical); leave `FOOTER_NOTE` as it is for Stage A and list it in the Stage B checklist — P2 (one right answer per command) and "no new string" — if wrong, a Forever user sees a wrong position number, a cosmetic error.
- **F9 (Low; T3 wording).** `SF = { editing = SF.FirstMode() }` is impossible at line 18. The plan gives `ChallengeModeActive` a Forever answer of `false`, but calls it "its existing no-data answer", which is `nil` (`nil` triggers the M+ fallback in the mode).
  Ruling: write `editing = nil` at line 18 and set `SF.editing = SF.FirstMode()` right after `FirstMode` is defined; keep `false` for `ChallengeModeActive` and drop "existing" from the wording — `false` is the safer answer and Focus gates `mplus` anyway — if wrong, a load-time error or an implementer returning `nil`, which reopens the keystone fallback.
- **F10 (Low; mutation coverage).** The T1 CAMELOT test misses its named mutation when MAINLINE is set. The T5 "16001" test names the `#s == 5` mutation, which only the 11509 test catches. The T1 scan checks `Allows` surfaces but not ids, so a typo such as `Allows("overlay", "keystones")` passes and silently never gates on Forever.
  Ruling: the CAMELOT test sets only `ID = CAMELOT = 18` (no MAINLINE); move the `#s == 5` mutation note to the 11509 test; extend the scan so a literal `Allows("s", "id")` id must appear under some feature's `surfaces[s]`, or must be listed as a known ungated id — the Global Constraints require each critical test to name a mutation that makes it fail — if wrong, a gate typo ships with every test green.
- **F11 (Low; counts).** The tests listed are 13, 15 and 21 against the minima of 14, 16 and 22 for Tasks 1-3, and T1's Files names `checks_spec` with no test for it. The grand total (74 listed, 1992 + 74 = 2066 ≥ 2064) still holds.
  Ruling: lower the T1/T2/T3 minima to 13/15/21 and drop `checks_spec` from T1's Files — padding a test to hit a count produces assert-nothing tests — if wrong, a reviewer bounces a task for a missing test that was never specified.
- **F12 (Low; TDD step).** "Expected: the new tests FAIL" is false for the regression guards. These pass before the change: T2 ToggleBag, "on Retail 15 still fails" and "GetBagIDs Retail 0-5"; T3 "on Retail the same reads still ask the game" and "on Retail the Focus page still starts on M+"; T4 "a Retail login is unchanged" and "on Retail the report has no Forever line".
  Ruling: mark them "characterization: passes before and after", and run their named mutations by hand — red-first does not apply to a guard — if wrong, an implementer breaks code to get a red run, or reports a false TDD violation.
- **F13 (Low; anchors).** Every line number is d17f92b's. Task 1's insert after line 123 shifts every later Adapter anchor for Tasks 2 and 3, and Task 2 shifts them again for Task 3.
  Ruling: implementers locate code by function name and comment, and treat the line numbers only as hints — the code is the source of truth — if wrong, an edit lands in the wrong function.
- **F14 (Low; T4 test setup).** forever_spec needs Boot.lua, Checks.lua, Commands.lua and the bags window loaded, and `A.globals = Globals.AllPresent(A)` set before `PLAYER_LOGIN`. Without it, every required bags check fails and "the bags window opens" cannot pass. Env.LoadBank followed by Env.LoadGuild loads Buttons, Overlays, GroupView and the others twice in one SB.
  Ruling: state both in the brief. For the guild test, after Env.LoadBank load only Snapshots, GuildButtons and GuildBankWindow — the helpers were never used together — if wrong, the tests fail for set-up reasons, or double handlers mask a real double notice.
- **F15 (Low; Global Constraints wording).** Task 5 creates `docs/.../stage-b-checklist.md`, which is not in the constraint's list of new files. "On Forever nothing falls back to a guessed number" conflicts with `BagLayout` falling back to the Retail table on a malformed Forever `Enum.BagIndex`.
  Ruling: add the checklist to the list of allowed new files, and accept the Retail fallback on Forever as documented, because the bank is off through Safe Mode, bags 0-5 are identical on both clients, and a malformed table also fails the `foreverValue` check — neither changes any code — if wrong, a reviewer blocks the task on a wording conflict.
- **F16 (Low; T2 test mechanics).** The cache test's "`__index` counter on the table" counts only lookups of absent keys.
  Ruling: use an empty proxy table whose `__index` counts each read and forwards it to the real table — this counts every read — if wrong, the test is fragile or measures nothing.
- **F17 (Low; T5 release.sh).** `name_lines="$(luajit scripts/interfaces.lua ...)"` under `set -e` aborts silently on an unknown number, where today it prints "Note: ... left out". `--help` prints `sed -n '2,20p'`, so a longer header can cut off the `--forever` line.
  Ruling: write it as `lines="$(luajit scripts/interfaces.lua "$INTERFACES")" || fail "the TOC lists an Interface number that is neither Retail nor WoW Forever: $INTERFACES"`, and widen the help range to the header's real end — "every Retail behaviour kept" plus an explicit STOPPED message — if wrong, a typo in the TOC stops a release with no message.
