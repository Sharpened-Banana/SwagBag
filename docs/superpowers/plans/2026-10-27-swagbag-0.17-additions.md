# SwagBag 0.17: Alt Gold and Currencies, Item-Level Colors, Per-Bag View. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three player-facing additions in one release, 0.17.0: every character's gold and currencies in the
footer's tooltips, the user's own item-level colors, and a per-bag view in the bags and bank windows.

**Architecture:** Each feature gets one small pure Engine module that owns its rule (Engine/Wealth.lua,
Engine/IlvlColors.lua, Engine/PerBag.lua), tested on its own with busted; the UI files that already draw
the footer, the overlays, the list rows and the two windows call into it. Alt data goes through
Engine/AltData.lua's provider chain (Syndicator first, SwagBag's own store after), like item counts do today.

**Tech Stack:** Lua 5.1 (WoW), busted-style specs run by `luajit spec/runner.lua`, luacheck; `scripts/check.sh`
runs everything.

**Spec:** `docs/superpowers/specs/2026-10-27-swagbag-0.17-alt-gold-ilvl-colors-per-bag-design.md` (read it
first; this plan argues from it). Main design: `docs/superpowers/specs/2026-09-30-swagbag-design.md`.

## Global Constraints

- Every WoW API (`C_*`, `Enum`, globals such as `GetMoney`) is named only in `SwagBag/Core/Adapter.lua`,
  comments included (check.sh rule 3). New Adapter functions get a fake in `spec/mock_adapter.lua` and, if
  they read a game API, an entry in the Adapter's API checks table (the `{ path = ..., window = ..., required
  = false }` list near line 2250).
- Every value read from the game is checked with `isSecret` / `A.IsSecret`; a secret is treated as unknown.
- Every user-visible string lives in `SwagBag/Locale/enUS.lua` (`L.*`). Plain English, short; follow the voice
  of the neighbouring strings.
- New Engine files go in `SwagBag/SwagBag.toc`: Wealth.lua right after Engine/AltData.lua, IlvlColors.lua and
  PerBag.lua right after Engine/GridLayout.lua. `scripts/toc_check.lua` must pass.
- Nothing changes for a player who touches nothing: the footer looks the same, item levels stay white
  (`overlays.ilvlColors` default false), `bags.view` / `bank.view` defaults stay `"sections"`.
- Settings are plain values (boolean, number, text), so per-character overrides, profiles and share strings
  carry them with no change to Engine/Profiles.lua. Read-only settings (Safe Mode, newer schema): every write
  answers `L.SETTINGS_READONLY` as today and changes nothing.
- No polling, no OnUpdate: events and `SB.Debounce` only.
- Comments: match the files' density and style (a header contract at the top of each new module, listing its
  functions as the existing modules do).
- Commits as lonezebra with the GitHub no-reply email (already the repo's git config). Each ends with:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01SW5eeGTDMFqFCh4qdWCK1M`.
- Every task ends with `./scripts/check.sh` printing `ALL CHECKS PASSED`.

## Review Focus

1. **Saved data from 0.16 and earlier**: `SwagBagDB.chars[key]` has no `money` / `currencies`. Such a
   character is simply left out of the tooltips; nothing errors, nothing shows "0". (Task 1 test.)
2. **Damaged `overlays.ilvlSteps` text** (hand-edited, "abc", "680:pink", 5 steps, level 0 or 100000):
   bad steps are dropped, the rest still color, nothing errors. (Task 4 test.)
3. **A bag slot with no bag equipped** (size 0) or a bank tab not bought: no section for it in the per-bag
   view, no empty header. (Task 6 test.)
4. **Two characters with the same name on different realms**: both lines show, each with its realm; one
   name alone shows no realm. (Task 3 test.)
5. **Switching to the per-bag view while the mouse is over an item**: the layout waits as every other view
   change does (W.RequestLayout / BW.view.RequestLayout hold under the mouse); nothing moves under the cursor.
   (Task 7 and Task 8 tests.)

Ledger: record rulings and deferred findings in `docs/superpowers/plans/2026-10-27-swagbag-0.17-ledger.md`,
as every earlier build did.

### Task 4: Item-level colors: the rule and where it shows (Engine/IlvlColors.lua)

**Files:**
- Create: `SwagBag/Engine/IlvlColors.lua`
- Modify: `SwagBag/Core/Config.lua` (defaults `overlays.ilvlColors = false`, `overlays.ilvlSteps = ""`, with a
  comment), `SwagBag/UI/Overlays.lua` (top-left text), `SwagBag/UI/ListRows.lua` (ilvl column),
  `SwagBag/SwagBag.toc`
- Test: `spec/ilvlcolors_spec.lua` (new), `spec/overlays_spec.lua`, `spec/listrows_spec.lua`

**Interfaces:**
- Produces:
  - `IC.PALETTE = { gray = { 0.62, 0.62, 0.62 }, white = { 1, 1, 1 }, green = { 0.12, 1, 0 }, blue = { 0, 0.44, 0.87 },
    purple = { 0.64, 0.21, 0.93 }, orange = { 1, 0.5, 0 } }`, `IC.ORDER = { "gray", "white", "green", "blue",
    "purple", "orange" }`, `IC.MAX = 4`, `IC.MIN_LEVEL = 1`, `IC.MAX_LEVEL = 9999`.
  - `IC.Parse(text) -> steps`: `{ { level = n, color = name } }` in text order; a part that is not
    `<integer>:<palette name>` or out of range is dropped; at most `IC.MAX` kept (the first ones). Never errors
    on a non-string (returns `{}`).
  - `IC.Format(steps) -> text` (`"680:green,690:blue"`).
  - `IC.Pick(steps, level) -> r, g, b | nil`: the color of the highest step whose level ≤ `level`; steps sorted by
    level (stable, so with two steps of one level the earlier row wins); nil below the lowest step.
  - `IC.For(level) -> r, g, b | nil`: nil unless `overlays.ilvlColors` is true; else `IC.Pick(IC.Parse(
    Config.Get("overlays.ilvlSteps")), level)`, the parse cached until `SB_CONFIG_CHANGED`.
  - `IC.Fill(equipped) -> steps`: `{ { level = floor(e), color = "green" }, { level = floor(e) + 10, color = "blue" },
    { level = floor(e) + 20, color = "purple" } }`; `{}` when `equipped` is not a positive number.
- Overlays: after `r.topLeft:SetText(top)`, the color is `IC.For(d.ilvl)` when the top text is the item level,
  else white (1, 1, 1); a keystone's "+12" keeps white. ListRows: `row.ilvl:SetTextColor` the same way from
  `SB.Sort.Ilvl(record)`.
