## TOP 8 FOR SWAGBAG (ranked)

1. **12.1.5 removes the deprecated global shims (Blizzard_DeprecatedItemScript and others) - live 2026-10-13.** Any SwagBag (or Pawn/Auctionator-integration) code calling global `GetItemInfo`, `GetItemInfoInstant`, `GetItemCount`, etc. will hit nil on Oct 13. Risk, High. Action: grep the codebase this week for non-namespaced item/currency/socket globals; replace with `C_Item.*`, `C_CurrencyInfo.*`, `C_ItemSocketInfo.*`; test on the 12.1.5 PTR before Oct 13. Also verify third-party libs you call.
2. **Bagnon's "action blocked" fix reveals a combat-taint trap for custom bag windows (Bagnon 12.1.5, 2026-09-29).** Fix = pre-create item buttons for the max slot count at startup, one button per slot (no shared pool), check for oversized bags before combat, and block bag dragging in combat. SwagBag uses secure Blizzard item buttons, so the same failure class applies (new bag or oversized bag equipped in combat, buttons created in combat). Risk, Medium-High. Action: audit SwagBag button creation for in-combat paths; adopt pre-create-at-login plus pre-combat size check; add a Safe Mode trigger for ADDON_ACTION_BLOCKED involving SwagBag.
3. **12.1.5 adds Ascendant Venomstones (10 per upgrade, for S2 weapon/trinket/necklace ilvl boost) and the weekly crest cap lifts the week of Oct 20.** New currency plus a new upgrade-ish track. Opportunity, High. Action: add Venomstones to footer currency choices and to the M+/Raid/Delves focus-mode "relevant items", and confirm the upgrade-track overlay does not mislabel Venomstone-boosted items (ilvl above the old S2 Myth ceiling of 337, PTR moved it about +7). Check the track string/bonus IDs on a boosted item on PTR.
4. **Midnight "secret values" regime continues to widen, but aimed at units/auras/combat data, not containers.** 12.1.0 and 12.1.5 changes are aura/unit/damage-meter focused. `C_TooltipInfo` aura calls return secrets in combat/M+; item tooltips are not newly restricted. `GameTooltip_AddMoneyLine` (12.0.7) exists because money in tooltips could taint. Risk, Low-Medium. Action: keep all tooltip money output on `GameTooltip_AddMoneyLine` or `GetCoinTextureString`; use `issecretvalue()` guards on any tooltip-derived text read during M+/encounters (your low-consumable warning and per-section price totals).
5. **WoW: Forever (2026-11-04) shares Mainline UI/API (12.1.5 family, C_Container, C_Item exist) with Midnight restrictions, and a bag-addon market exists but is crowded.** Bagnon and Baganator already ship Forever flavors; ForeverBags (new, 262 downloads) exists. Opportunity, Medium, deferred. Action: do not build now; but avoid hard dependencies on Retail-only APIs in the core so a Forever TOC could be added in 2027 (use capability probes, not WOW_PROJECT_ID). Forever bank is about 96 slots and has 1 reagent bag slot.
6. **Baganator ships weekly-ish and now claims 12.1.0 across Retail plus all Classic flavors (v833, 2026-10-01); BetterBags has a Midnight category module (v1.8.0, 2026-09-06).** Competitors are not stalling. Risk, Medium. Action: keep the switcher story (setup simplicity, focus modes) as the differentiator; the Nov rule builder with Baganator-string import is the right defensive move; ship it before Season 3 / 12.2.
7. **12.2 "Eclipse" (winter, date TBA) with Season 3: new M+ pool (Thraegar's Stand plus returning dungeons), new crest/track set likely, spec-based top 1%/5% ranking, housing expansions (mannequins, copy-paste decor), transmog restrictions removed in 12.2.5.** Opportunity, Medium. Action: make every season-specific list (crests, track names, consumable watch list, keystone dungeon names) data-driven so a Season 3 patch is a data edit; plan the "uncollected transmog" overlay knowing 12.2.5 removes armor-type restrictions (changes "can I use this appearance" logic; do not hardcode armor-type rules).
8. **Housing decor is account-wide storage (not bags) and 12.1 added 272 decor items plus dye rework freeing bag space.** The planned "uncollected decor overlay" is feasible but decor items in bags are collectible/learnable via C_HousingCatalog. Opportunity, Low-Medium. Action: when you build it, use `C_HousingCatalog.GetCatalogEntryInfoByItem` (note 12.0.5 removed its `tryGetOwnedInfo` param); no urgency.

## 3. WoW: Forever and Classic flavors

- Launch 2026-11-04 15:00 PST (LIKELY, multiple sites). Needs normal subscription. Classic Forever client 1.60.1, TOC 16001, Lua 5.1 (third-party developer guide, UNVERIFIED as authoritative).
- API: shares "the vast majority" of 12.1.5 Mainline APIs; Midnight-style combat restrictions apply; C_Container, C_Item, C_TransmogCollection exist; legacy globals are gone; secure snippets reportedly failing to compile in beta (UNVERIFIED, single third-party guide, https://wowforeverguides.com/addons/developers). Capability probes recommended over `WOW_PROJECT_ID`.
- Bags/bank: fifth bag slot is a reagent bag; default bank about 96 slots (developer quote, Sept 16, 2026); mounts window and transmog reduce bag pressure (https://www.warcrafttavern.com/forever/news/changes-to-bags-banks-in-world-of-warcraft-forever/). Smaller inventories than Retail imply less need for category views; more for alt-tracking and sorting.
- Demand/supply: Bagnon ships an official Forever flavor (12.1.5 release 2026-09-29 mentions Forever compatibility); Baganator v833 (2026-10-01) lists "Classic Forever 1.60.1"; ForeverBags created 2026-09-04, 262 downloads (https://www.curseforge.com/wow/addons/foreverbags). Third-party lists name Bagnon, AdiBags, Baganator. So bag addons are expected on day one, and incumbents are there first.
- Impact: Opportunity, low-medium; secure-template-dependent addons (SwagBag uses secure Blizzard item buttons) carry porting risk if secure snippets are broken. Action: stay Retail-only; revisit in Jan 2027 after seeing Forever API stability and whether secure item buttons work. Meanwhile keep a core/UI split and use capability probes.
- Other Classic flavors (MoP 5.5.4, Wrath 3.80.1, TBC 2.5.6, Era 1.15.9) are served by Baganator/Bagnon; no reason to chase.
